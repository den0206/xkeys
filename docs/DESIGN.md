# App Mate 仕様

現在の実装に対応する動作と保存形式。開発手順・確認状況は[IMPLEMENTATION.md](IMPLEMENTATION.md)、外観の参照は[画面モック](mockups/index.html)にまとめる。

## 対応環境と範囲

macOS 26.0以降のSwiftUI / SwiftDataアプリ。App Sandboxを有効にし、ネットワーク接続Entitlement・iCloud同期・自動起動を使わない。解析はSecurity / CMSDecoder、暗号化はCryptoKit、鍵導出はCommonCrypto、認証はLocalAuthentication、通知はUserNotificationsを使用する。外部依存はない。

Team・App管理、資格情報の保管、暗号化メモ、一括取り込み、期限通知、削除と復元、バックアップ、CIコピーに対応する。V1.1の横断検索・種別フィルター・メニューバーも実装している。オンライン失効確認、App Store Connect API照合、CIへの直接送信は対象外。Mac App Store配布・審査は未確認。

## 管理対象と所属

| 対象 | 解析と保管 |
| --- | --- |
| .p8 | 16KiBまでのP-256秘密鍵の構造を確認。用途・Key IDを手入力し、ASC APIではIssuer IDも入力。期限なし |
| .cer | X.509証明書から名前・期限・Team等を取得できる範囲で抽出 |
| .p12 | 選択後にパスワードを入力。複数証明書があれば表示・期限の基準を選択。元ファイル全体を保持 |
| .mobileprovision / .provisionprofile | CMS署名を確認し、plistから期限・Team・Bundle IDを抽出 |

解析はApple発行元の信頼性・オンライン失効・証明書と秘密鍵の対応を保証しない。.p12はSecurityフレームワークが読み込める方式に限る。読み込み時に他アプリのログインキーチェーンへ鍵を永続取り込みしない。

Team IDは英大文字・数字10文字で一意。AppはTeamとBundle IDで識別し、同じTeam内のBundle IDは大文字小文字を区別せず重複を拒否する。Bundle IDは英数字・ハイフン・ピリオドを許可し、空の区切り要素とワイルドカードを拒否する。

Team名・App名とAppのプラットフォームを編集できる。Team ID・Bundle ID・所属Teamは固定し、別の識別子は新規登録する。登録時にプロファイルをドロップして名前・Bundle ID・Teamを入力できる。

Appは本体ターゲットも兼ね、任意のparentAppIDで同じTeamの本体に所属する。階層は本体と配下ターゲットの2段まで。所属変更でもUUID・Bundle ID・暗号化AADは維持する。既存のAppはparentAppIDがnilの本体として扱い、任意属性の追加によりSwiftDataで移行する。本体選択時は配下の資格情報を集約し、ターゲット別にも絞り込める。取り込みはBundle ID完全一致を優先し、ワイルドカードが1ターゲットだけに一致すればそのターゲットを選ぶ。曖昧な場合は画面で選択する。未登録の具体的なBundle IDは確認してターゲット追加でき、前方一致だけでグループ化しない。

証明書・.p12・.p8はTeam所属で、チームごとの「鍵・証明書」に表示する。用途別の3つの入口は置かず、一覧内で種類と用途を絞り込む。App画面は専用プロファイルのみを表示し、チームの一覧へのリンクを置く。アプリの利用数は推測しない。チームにAppが0件でも鍵・証明書を取り込める。プロファイルは1つのAppに所属し、TeamとBundle IDの一致を確認する。共有先ごとの複製や関連解除は行わない。Appが0件でもTeam共有資格情報は保持する。App・資格情報が残るTeamの削除は拒否する。

## 保存モデルと認証

| 実装 | 役割 |
| --- | --- |
| DeveloperTeam | UUID、Team ID、表示名、Appとの関連 |
| ManagedApp | UUID、Team、Bundle ID、表示名、プラットフォーム、所属アプリUUID（任意）、作成日時、メモblob参照、削除日時 |
| StoredCredential | UUID、所属、名前・形式・ハッシュ・期限・鍵識別情報、blob参照、置き換え関係、削除・手動失効日時 |
| CredentialPayload | 暗号化対象の元ファイル、任意の.p12パスワード、メモ |
| BackupChange / BackupCheckpoint | 未バックアップ変更、最終バックアップ日時、設定、通知期間の管理 |
| AppPreferences | 通知日数・表示設定・CIテンプレート。CheckpointのDataへ保存 |
| VerificationRecord | ヘルプから開く技術検証用の保存記録。製品バックアップ対象外 |

メタデータをSwiftDataへ、秘密情報をAES-GCMの暗号化blobへ保存する。メモと保存済み.p12パスワードはSwiftData・ログ・検索へ平文保存しない。Appのメモは別blob、資格情報のメモはCredentialPayloadに含める。メモは各64KiBまで。

暗号鍵はdata protection Keychainの端末専用・同期なしの項目に保存する。`WhenUnlockedThisDeviceOnly` と `userPresence` を指定する。暗号鍵が取得できない既存金庫を、新しい鍵で上書きしない。

表示・書き出し・コピー、メモの読み書き、利用者による削除・完全削除・復元では `deviceOwnerAuthentication` で毎回認証する。Macのパスワードはシステム画面に入力し、アプリは保存しない。認証失敗・取消・ロックによる認証世代の変更では、その操作を実行しない。

秘密表示は手動ロック・画面ロック・スリープ等で破棄する。パスワード表示は最長5分、メモ・取り込み・復元途中の内容は無操作5分で閉じる。取り込み中のファイルと入力内容はアプリ切り替えでは保持し、画面ロック・スリープ・取り込み画面を閉じたときに破棄する。.p12パスワードの保存は初期オンで、未保存なら表示・コピーできない。

資格情報のAADはUUID・所属・ファイルのハッシュ等に結び付ける。既存のメタデータversion 1 / 2を維持し、blobIDを持つ項目はAADへblob参照も含める。AppメモのAADはApp UUID・Team UUIDに結び付ける。更新は別UUIDのblobを保存・読み戻し検証し、DBの参照を切り替える。失敗時はrollbackし、新規blobを除去する。DBが参照しない旧blobは通常の回収処理で除去する。

## 取り込みと置き換え

ファイル選択・ドロップで複数ファイルまたはフォルダを指定し、1件ずつ解析・所属の確認・認証・保存を行う。各16MiB、一括200対応ファイル、フォルダ探索10,000項目まで。フォルダ内のリンク・隠し項目・パッケージ配下を追跡しない。成功とスキップの結果、失敗理由を表示する。元ファイルの削除オプションはない。

.p8はASC / APNs / Sign in with Appleの用途、英大文字・数字10文字のKey IDを確認する。ASCだけUUID形式のIssuer IDを求める。.p8にはTeam IDが含まれないため、画面に表示した登録先Teamに割り当てる。それ以外の形式でTeamを取得できない場合は、選んだTeamへの割り当てを明示確認する。

.cerの中間CA証明書はBasic ConstraintsのCA属性と、正規化したSubject・Issuerが異なることから識別する。ファイル名には依存しない。Team IDは対象外とし、Teamへの割り当て確認を求めず、選択中のTeamを保管先として共有領域に保存する。分類は既存のkindに保存し、一覧・詳細・バックアップ復元後にも維持する。この分類は発行元の信頼性や署名検証を保証しない。既存データのkindは暗号化AADに含まれるため、自動的には書き換えない。

同じ共有範囲の同一ファイルはSHA-256で重複を拒否する。置き換えは同じTeam・共有範囲・形式・用途の旧資格情報を選び、旧→新と保管先を確認した場合だけ実行する。旧ファイルは保持し、通常一覧・通知から除外する。「置き換え済みを表示」から再表示・認証付きの通常一覧への復帰ができ、新しいファイルも残す。

## 期限・通知・検索

| 状態 | 条件 |
| --- | --- |
| 手動失効 | 利用者が設定。期限計算より優先 |
| 置き換え済み | 後継への参照あり。通常一覧から除外 |
| 期限切れ | 期限が現在時刻と同じ、または過去 |
| 24時間以内 | 期限まで24時間未満 |
| まもなく期限 | 期限まで30×24時間以内。残り日数を切り上げて表示 |
| 有効 / 保管中 | 30日より先 / 期限なし |

通知は初期値30・7・1日前と当日。Macのタイムゾーンで各対象日の9時、当日は9時と期限時刻の早い方に予約し、過去の期限通知は予約しない。削除済み・置き換え済み・手動失効は通知対象外。Dockバッジはまもなく期限の資格情報を重複なく数える。

予約はデータと設定の変更、起動・復帰・タイムゾーン変更、実行中の1分周期で見直す。アプリ側の上限は近いものから60件で、残件を設定に表示する。OSの予約・配送保証値ではない。終了中の補充・配送を保証しない。通知内容は一般文と移動先UUIDで、通知から該当項目へ移動する。通知拒否時も一覧は利用でき、設定から許可・Macの通知設定への案内を利用できる。

横断検索は全Team・Appの名前、Bundle ID、Team ID、ファイル名、種類、Key ID、Issuer ID等のメタデータが対象。複数語はAND検索し、元ファイル・メモ・パスワードを開かない。種別フィルターは全種類・.p8・.cer・.p12・両プロファイル形式。検索中は追加先の誤認を防ぐためファイル追加を無効化し、サイドバー移動で検索を解除する。

メニューバーはアプリ実行中に表示し、期限切れ・30日以内・全件・未バックアップ件数を確認できる。既存ウィンドウを前面へ出し、なければ開く。メニューバーとDockバッジは設定でオフにできる。

## バックアップと復元

フルバックアップは全Team・App・資格情報、元ファイル、メモ、保存済みパスワード、設定、削除・手動失効・置き換え関係を含む。金庫の暗号鍵、Mac固有の通知許可とバックアップ履歴は含めない。選択エクスポートは選んだAppと配下の全ターゲット・必要なTeam・資格情報を含め、共有ファイルは重複させず、全体設定を含めない。

保存先は毎回利用者が選び、既存ファイルを上書きしない。パスワード保護を初期値とし、パスワードなしは再確認する。バックアップ用パスワードは保存せず、忘れた場合の回復機能はない。個別書き出しは元形式で、書き出したファイルは金庫の暗号化保護の対象外になる。

### 固定形式

| 項目 | 値 |
| --- | --- |
| 拡張子・初期ファイル名 | `.appmatebackup` / `AppMate_yyyyMMdd_HHmmss.appmatebackup` |
| 内容種別 | `public.data`。独自UTType登録・ファイルを開く操作からの復元は未対応 |
| 先頭 | ASCII `APPMATE` とNULの8バイト、続いてbig-endian UInt32のJSONヘッダ長 |
| ヘッダ | 最大4,096バイト。version 1、protection、payloadLength、保護方式ごとの情報 |
| 保護あり | PBKDF2-HMAC-SHA256、600,000回、ランダムsalt 16バイト、導出鍵32バイト |
| 暗号文 | AES-256-GCM combined形式（nonce 12バイト・暗号文・tag 16バイト）。先頭からヘッダ末尾までをAADに使用 |
| 保護なし | JSON payloadと、ヘッダ内のSHA-256小文字hex。破損検出用で真正性は保証しない |
| パスワード | 正規化なしUTF-8、6文字以上・1,024バイト以内 |
| 内容 | snapshot.version 3。所属アプリUUID、メタデータ、元ファイルのbase64、メモ等。Dateは2001-01-01 UTCからの秒数 |
| 上限 | 元ファイル各16MiB・合計32MiB、payload 64MiB、ファイル全体64MiB+8,192バイト |
| 件数 | Team 1,000件、App・資格情報は各10,000件 |

旧内容version 1 / 2も読み込む。旧versionを名乗り新しい項目を持つ内容は拒否する。旧アプリはversion 3を拒否する。未知の方式・バージョン・過剰なKDF処理量・不正な所属・参照・ハッシュは拒否する。復号失敗を保護なしとして読み直さない。

### 復元と変更記録

差分を新規・重複・競合に分け、競合ごとに現在／バックアップを選択する。Team ID・Team内Bundle ID・共有範囲とハッシュが一致する項目は既存UUIDへ関連を写し替える。同じUUIDが異なる実体を指す場合は全体を拒否する。差分確認後に現在の内容が変われば、再確認を求める。

未バックアップの件数とリマインダーは変更履歴を基にする。ただしApp・資格情報がすべて空で設定も初期値なら、Teamや過去の変更履歴が残っていても件数を0とし、リマインダーは予約しない。最近削除した項目や変更済みの設定はバックアップ対象として扱う。

マージは既存項目を残す。全体置き換えは現在の全データの事前退避が成功し、そのrevisionが差分確認時・実行時の内容と一致する場合だけ許可する。ただしTeam・App・資格情報がすべて空で設定も初期値の場合は、事前退避を不要とする。この場合も差分確認後に変更があれば実行を止める。退避の失敗・取消・その後の変更では置き換えない。既存の金庫鍵を維持し、復元blobの準備と読み戻し後、同じDB保存で参照切替と不要項目の除去を確定する。旧形式に設定がなければ現在の設定を保つ。

登録・編集・取り込み・メモ・削除・復元・設定等の変更を、データと同じトランザクションで記録する。フルバックアップ完了時は、スナップショットと同時に取得した変更UUID集合だけを保存済みにする。後続変更を残し、古いバックアップの完了で最新日時を巻き戻さない。個別書き出し・選択エクスポートは未バックアップ状態を解除しない。ファイル保存だけ成功し履歴更新に失敗した場合は、有効なファイルと未バックアップ表示を残す。

最古の未バックアップ変更から初期値7日後に1回通知する。期間を最古の変更UUIDで識別し、同期間で繰り返さない。日数は1〜365日またはオフに設定できる。

## 削除とCIコピー

削除は認証・確認後に行い、30日間は「最近削除した項目」から復元できる。Appと専用プロファイルの関連を保持し、親Appの復元時には同時に削除した子を戻す。共有鍵の削除は保管先チームを表示する。実際の利用Appは記録していないことを示す。Apple側の失効やCI設定は変更しない。

30日以上前の削除済み項目を、次回起動・所有者認証時に完全削除する。期限切れだけの項目は対象外。未削除・保持期限未満の子がある親Appは残す。置き換え履歴の再暗号化が必要な場合は認証後へ延期する。「すべて完全に削除」は確認と認証が必要。元ファイルと既存バックアップは削除せず、SSD上の物理消去を保証しない。

CIコピーは.p8 / .p12のbase64、Key ID、Issuer ID、Team ID、保存済み.p12パスワードを1項目ずつ認証して行う。値を画面に出さず、検証した変数名・リポジトリ名で秘密値を含まない `pbpaste | gh secret set ...` コマンドを表示する。テンプレートは設定で追加・編集でき、最大100件。Bitrise等へは元形式で書き出す。

クリップボードへ `currentHostOnly` と `org.nspasteboard.ConcealedType` を指定し、60秒後にchangeCountが同じ場合だけ消去する。後からコピーされた内容を消さない。アプリ終了後のタイマー実行や、他アプリによる記録防止を保証しない。
