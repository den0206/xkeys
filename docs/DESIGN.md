# Xkeys 仕様

現在の実装に対応する動作と保存形式。開発手順・確認状況は[IMPLEMENTATION.md](IMPLEMENTATION.md)にまとめる。

## 対応環境と範囲

macOS 26.0以降のSwiftUI / SwiftDataアプリ。App Sandboxを有効にし、Apple Developer接続用のnetwork.client Entitlementを使い、iCloud同期・自動起動は使わない。解析はSecurity / CMSDecoder、暗号化はCryptoKit、鍵導出はCommonCrypto、認証はLocalAuthenticationを使用する。認証にはXcodesLoginKitを使用し、リビジョンと推移的な依存をPackage.resolvedで固定する。

Team・App管理、資格情報の保管、暗号化メモ、一括取り込み、削除と復元、バックアップ、CIコピーに対応する。横断検索と種別フィルターも実装している。オンライン失効確認、App Store Connect API照合、CIへの直接送信は対象外。Mac App Store配布・審査は未確認。

表示言語は日本語と英語。OSの言語設定に従い、`Localizable.xcstrings` で切り替える。資格情報の種類（`kind`）や.p8用途の登録名など、保存データと暗号化のAADに入る文字列は言語にかかわらず固定し、表示時だけ翻訳する。CI用Secretファイルのコメントも表示言語で書き出す。

## 管理対象と所属

| 対象 | 解析と保管 |
| --- | --- |
| .p8 | 16KiBまでのP-256秘密鍵の構造を確認。用途（複数可）を選び、ASC APIではIssuer IDも入力。Key IDはファイル名 `AuthKey_<Key ID>.p8` から初期入力し、変更できる。期限なし |
| .cer | X.509証明書から名前・期限・Team等を取得できる範囲で抽出。Apple Developerから再取得できるため、取り込み画面で保存は任意であり、署名には.p12が必要と案内する |
| .p12 | 選択後にパスワードを入力。複数証明書があれば表示・期限の基準を選択。元ファイル全体を保持。基準以外の証明書も名前・期限・フィンガープリントを記録し、「同梱の証明書」として表示する |
| .mobileprovision / .provisionprofile | CMS署名を確認し、plistから期限・Team・Bundle IDを抽出 |

解析はApple発行元の信頼性・オンライン失効・証明書と秘密鍵の対応を保証しない。.p12はSecurityフレームワークが読み込める方式に限る。読み込み時に他アプリのログインキーチェーンへ鍵を永続取り込みしない。

Team IDは英大文字・数字10文字で一意。AppはTeamとBundle IDで識別し、同じTeam内のBundle IDは大文字小文字を区別せず重複を拒否する。Bundle IDは英数字・ハイフン・ピリオドを許可し、空の区切り要素とワイルドカードを拒否する。

Team名・App名とAppのプラットフォームを編集できる。アプリ画面はプロファイルがないものも含めてターゲット単位にまとめ、各行のメニューから編集・削除できる。通常の削除はターゲット登録と配下の全プロファイルをまとめて対象にし、本体の場合は全子ターゲットも含む。削除確認に登録名・Bundle ID・件数を表示する。ファイルだけの削除は詳細メニューの「このプロファイルだけを削除…」、一括の場合は「ファイルだけを一括削除…」と明記し、登録を残す。選択中のターゲットを削除した場合は「すべて」の表示へ戻す。Appのアイコンは作成後も「アプリを編集…」で色または1MB以下のPNG・JPEG・SVG画像に変更でき、保存時に反映する。色を選ぶと画像アイコンを解除する。Team ID・Bundle ID・所属Teamは固定し、別の識別子は新規登録する。登録時にプロファイルをドロップして名前・Bundle ID・Teamを入力できる。

Appは本体ターゲットも兼ね、任意のparentAppIDで同じTeamの本体に所属する。階層は本体と配下ターゲットの2段まで。所属変更でもUUID・Bundle ID・暗号化AADは維持する。既存のAppはparentAppIDがnilの本体として扱い、任意属性の追加によりSwiftDataで移行する。本体選択時は配下の資格情報を集約する。サイドバーはアプリを1行ずつ表示し、ターゲットは行にせずターゲット数を出す。ターゲットの絞り込みはアプリ画面上部のボタンで行い、赤い帯と要対応の件数は絞り込み中もアプリ全体の数を表示する。取り込みはBundle ID完全一致を優先し、ワイルドカードが1ターゲットだけに一致すればそのターゲットを選ぶ。曖昧な場合は画面で選択する。未登録の具体的なBundle IDは確認してターゲット追加でき、前方一致だけでグループ化しない。

証明書・.p12・.p8はTeam所属で、チームごとの「鍵・証明書」に表示する。用途別の3つの入口は置かず、一覧は証明書・プロファイル・鍵（.p8）の種類別セクションに分ける。各セクションは開閉でき、開閉の状態は保存しない。閉じたセクションに要対応の項目があれば件数を赤く表示する。App画面はターゲットごとに専用プロファイルを表示し、チームの一覧へのリンクを置く。アプリの利用数は推測しない。チームにAppが0件でも鍵・証明書を取り込める。プロファイルは1つのAppに所属し、TeamとBundle IDの一致を確認する。共有先ごとの複製や関連解除は行わない。Appが0件でもTeam共有資格情報は保持する。App・資格情報が残るTeamの削除は拒否する。サイドバー上部のチーム切り替えで表示するチームを選び、そのチームのアプリと鍵・証明書だけをサイドバーに出す。全チームの期限切れ・30日以内は「対応が必要」にまとめる。チーム切り替えメニューの「登録済みチームを管理…」はAppleの接続状態によらず登録済みの全チームの名前・Team IDを表示し、各行から編集・削除できる。同じメニューにも表示中のチームの編集・削除を置く。チームの削除はこの削除画面だけで行い、編集画面には置かない。削除画面は対象名とTeam IDを表示し、最近削除した項目を含む所属データが残る場合は理由を表示して削除を無効にする。

プロファイルは、内部の `DeveloperCertificates` に含まれる証明書ごとのSHA-256を `signingCertificateDigests` に保存する（最大100件）。同じTeamの.cer・.p12のフィンガープリント（証明書DERのSHA-256。.p12は同梱の証明書を含む）と一致すれば、プロファイルの「使う証明書」、証明書の「使っているアプリ」として表示する。使っているアプリは、一致したプロファイルの所属Appを本体ごとにまとめ、ターゲット名（本体は「本体」）を添える。一致した証明書がすべて期限切れのプロファイルは「証明書が期限切れ」とし、要対応に数える。この値は表示用の派生データで、AADとバックアップには含めない。期限切れの判定は一致した証明書それぞれの期限で行う。.p12の同梱の証明書（`p12Certificates`）も同じ扱いで、AADとバックアップに含めない。この項目を持たない既存のプロファイルと、復元したプロファイルは、次の所有者認証のあとで元ファイルを読み直して求める。.p12はパスワードを保存している場合だけ読み直し、保存していなければ「未確認」と表示する。読み直すまではつながりを表示しない。読み直せないファイルは空として扱い、毎回は読み直さない。読み直しは未バックアップの変更として記録しない。

## Apple Developerへの接続

チームの新規登録はApple Developerへのログインと所属チーム選択で行う。Team IDの手入力は設けない。サインインはApple Account、パスワード、必要な場合は6桁の確認コードの順に1画面ずつ進む。保存済みの接続が有効ならチーム選択から始める。XcodesLoginKitでApple Account・パスワードを認証し、信頼済み端末またはSMSの確認コードを受け付ける。フェデレーション認証・セキュリティキーは未対応として案内する。Apple側の規約に自動で同意しない。

Developer Portalの所属チーム一覧を取得し、英大文字・数字10文字のTeam IDと空でない名前を検証する。応答は1MiB、チームは1,000件までで、重複IDや不明な形式は拒否する。利用者が選択するまでTeamを保存しない。所属チーム一覧にはXkeysへの「登録済み／未登録」を表示し、行全体で選択できる。選択行を強調し、登録済みなら操作ボタンを「このチームを開く」に切り替える。同じTeam IDが登録済みなら既存のUUID・表示名を維持して開く。証明書・プロファイルのオンライン取り込みはチーム登録とは別の操作で行う。

アプリ全体で1つのApple接続を使い、セッションCookieは金庫の暗号鍵とは別のdata protection Keychain項目に保存する。WhenUnlockedThisDeviceOnly・同期なしとし、Apple Accountのパスワード・確認コードは保存しない。SwiftData・バックアップ・設定にはCookieを含めず、APIの本文やヘッダーをログ・エラー表示へ流さない。Cookieは許可したAppleドメインに限定し、HTTPSの接続先とリダイレクトを検証する。

設定の「セキュリティ」にApple Accountと名前を表示する。サイドバー下部にはコンパクトなアカウントメニューを配置する。チームが未登録のときは代わりに「チームを追加」を表示し、Keychainに残った保存セッションがあればそのアカウントを添えて所属チームの選択画面を開く。登録済みチーム一覧ではアカウント専用のセクションを設けず、現在確認済みの所属チームのカード内に緑文字の「ログイン中」と「ログアウト」ボタンを表示する。それ以外のカードには「ログイン」ボタンを表示し、対象チームへの所属を確認する。ログイン状態はチーム名の隣、操作ボタンは同じ行に揃える。チーム一覧を開いたときは保存セッションを検証・復元し、有効ならパスワードの再入力を求めない。「ログイン」「再ログイン」から認証画面を直接開ける。再ログインでは保存Cookieの自動復帰をせず、Apple Accountの入力から開始する。「ログイン中のApple Account」と「前回ログインしたApple Account」を区別し、メールアドレスを大きく表示する。「ログイン状態を確認」で明示的に有効性を確認し、「ログアウト」で保存した接続を削除する。アカウント情報はCookieと同じKeychain項目に保存する。チーム選択画面は入力欄ではなく認証済みアカウントを表示する。

起動時には接続せず、オンライン操作時に保存セッションを復元して有効性を確認する。期限切れと認証拒否で無効と確認できたセッションは削除し、再ログインを案内する。通信障害・サーバー障害・権限不足では保存セッションを削除せず、再試行を案内する。検証後のCookie更新はKeychainへ保存する。保存失敗時は接続完了として扱わない。

画面ロック・スリープでは通信とメモリ内の認証情報を破棄し、Keychainの保存セッションは維持する。終了後も保存セッションは残る。明示的な接続解除は保存セッションを削除し、登録済みデータと他アプリの接続は変更しない。削除失敗時も再利用を止め、削除再試行を案内する。チーム選択のキャンセルでは確立済みの接続を維持し、認証途中の取消では未確定の情報を破棄する。

## 保存モデルと認証

| 実装 | 役割 |
| --- | --- |
| DeveloperTeam | UUID、Team ID、表示名、Appとの関連 |
| ManagedApp | UUID、Team、Bundle ID、表示名、プラットフォーム、所属アプリUUID（任意）、作成日時、メモblob参照、削除日時 |
| StoredCredential | UUID、所属、名前・形式・ハッシュ・期限・鍵識別情報、blob参照、削除日時 |
| CredentialPayload | 暗号化対象の元ファイル、任意の.p12パスワード、メモ |
| BackupChange / BackupCheckpoint | 未バックアップ変更、最終バックアップ日時、設定 |
| AppPreferences | Dockバッジ。CheckpointのDataへ保存 |

メタデータをSwiftDataへ、秘密情報をAES-GCMの暗号化blobへ保存する。メモと保存済み.p12パスワードはSwiftData・ログ・検索へ平文保存しない。Appのメモは別blob、資格情報のメモはCredentialPayloadに含める。メモは各64KiBまで。

暗号鍵はdata protection Keychainの端末専用・同期なしの項目に保存する。`WhenUnlockedThisDeviceOnly` と `userPresence` を指定する。暗号鍵が取得できない既存金庫を、新しい鍵で上書きしない。

表示・書き出し・コピー、メモの読み書き、利用者による削除・完全削除・復元では `deviceOwnerAuthentication` で毎回認証する。取り込みは、1回の操作（ファイルの選択またはドロップ）で確認した全件を1回の認証で保存する。Macのパスワードはシステム画面に入力し、アプリは保存しない。認証失敗・取消・ロックによる認証世代の変更では、その操作を実行しない。

操作ごとに認証するため、アプリ全体の手動ロックは設けない。秘密表示は画面ロック・スリープ・選択や表示条件の変更で破棄する。パスワード表示は最長5分、メモ・取り込み・復元途中の内容は無操作5分で閉じる。取り込み中のファイルと入力内容はアプリ切り替えでは保持し、画面ロック・スリープ・取り込み画面を閉じたときに破棄する。.p12パスワードの保存は初期オンで、未保存なら表示・コピーできない。

資格情報のAADは、`XkeysCredential-v1` に続けてUUID・登録キー・所属・名前・形式・ハッシュ・期限・保存済みパスワードの有無・鍵の用途とKey ID・Issuer ID・blob参照を並べたJSON配列とする。AppメモのAADは `XkeysAppNote-v1|App UUID|Team UUID`。どちらも配布前に確定した形式で、項目を変える場合は新しい接頭辞と既存blobの移行処理を用意する。更新は別UUIDのblobを保存・読み戻し検証し、DBの参照を切り替える。失敗時はrollbackし、新規blobを除去する。DBが参照しない旧blobは通常の回収処理で除去する。

## 取り込み

ファイル選択・ドロップで複数ファイルまたはフォルダを指定し、1件ずつ解析・所属の確認を行う。確認が終わった全件は、最後に1回の所有者認証でまとめて暗号化保存する。各件は別々に保存し、1件の失敗はほかの件に影響しない。認証を取り消した場合は確認済みの内容を保持し、再試行できる。一覧画面へのドロップでは取り込み画面を開かず、.p12 のパスワードだけを小窓で確認する。.p8 の用途、保存先ターゲットの選択、Teamの割り当て確認、.p12 内の証明書の選択が必要な場合は、同じファイルで取り込み画面を開く。各16MiB、一括200対応ファイル、フォルダ探索10,000項目まで。フォルダ内のリンク・隠し項目・パッケージ配下を追跡しない。成功とスキップの結果、失敗理由を表示する。元ファイルの削除オプションはない。

.p8の中身は秘密鍵だけで用途を含まないため、用途は利用者が選ぶ。選択肢はASC、およびApple Developerの鍵のサービス（APNs・Sign in with Apple・DeviceCheck・Maps・WeatherKit・Media Services・その他）。Developerの鍵は複数のサービスを持てるため複数選択でき、別に発行されるASCはほかの用途と組み合わせない。用途は定義順のカンマ区切りで `keyPurpose` に保存する。既存の単一値はそのまま読み、AADは変更しない。新しい用途を含むバックアップは、この変更より前のXkeysでは読み込めない。英大文字・数字10文字のKey IDを確認し、ASCだけUUID形式のIssuer IDを求める。

取り込み画面の「Apple Developerから用途を取得」を押した場合だけ、保存セッションと保管先チームへの所属を確認し、Developer Portalの `services-account/QH65B2/account/auth/key/get`（`teamId`・`keyId`）から鍵の有効なサービスを読み取る。APNs・DeviceCheck・MusicKitはサービスID、それ以外はサービス名で用途に対応付け、不明なサービスは「その他のサービス」とする。取得した用途は保存前に変更できる。秘密鍵は取得しない。鍵一覧に見つからない場合（ASCの鍵など）は手動で選ぶ。応答は1MiB・鍵1,000件・サービス100件までで、不正な形式は拒否する。

保存した用途はApple側と自動同期しない。詳細の「用途」から手動またはApple Developerからの再取得で変更でき、認証後に元ファイル・メモ・保存済みパスワードを新しいAADで別blobへ暗号化し直してから参照を切り替える。登録名は用途とKey IDから作り直し、Key IDは変更しない。変更は未バックアップの変更として記録する。.p8にはTeam IDが含まれないため、画面に表示した登録先Teamに割り当てる。それ以外の形式でTeamを取得できない場合は、選んだTeamへの割り当てを明示確認する。

.cerの中間CA証明書はBasic ConstraintsのCA属性と、正規化したSubject・Issuerが異なることから識別する。ファイル名には依存しない。Team IDは対象外とし、Teamへの割り当て確認を求めず、選択中のTeamを保管先として共有領域に保存する。分類は既存のkindに保存し、一覧・詳細・バックアップ復元後にも維持する。この分類は発行元の信頼性や署名検証を保証しない。既存データのkindは暗号化AADに含まれるため、自動的には書き換えない。

同じ共有範囲の同一ファイルはSHA-256で重複を拒否する。更新したファイルは通常の取り込みで追加し、旧ファイルは利用者が削除する。新旧のファイルを関連付ける機能はない。

### Apple Developerからの取り込み

ログイン・確認コード送信・SMS送信・保存セッションの確認中は接続中の表示を出し、入力・再送信・戻る・チーム選択を無効にする。パスワードは初期状態で伏せ字にし、目のボタンで表示・非表示を切り替えられる。パスワードと確認コードは送信時に入力欄から消去する。2ファクタ認証の処理中は入力欄とコード入力の案内を進捗表示に切り替える。

登録済みチームの「鍵・証明書」画面から「Apple Developerから取り込む…」を開く。保存セッションの有効性と対象Team IDへの所属を確認し、未接続・所属不一致ならログインを案内する。証明書／プロファイルを切り替え、一覧から取り込み対象を選択する。初期選択は0件。取得可能な項目だけを表示し、通信失敗時に架空の項目へ切り替えない。

上部の「ファイルを追加」→「Apple Developerから取り込む…」でも、登録済みチームを選んで同じ画面を開ける。全件表示中や検索中も利用できる。Mac上のファイルを追加する操作は、保管先のチームまたはアプリを選択してから行う。「登録済みチームを管理…」にもログイン中チームの「取り込む…」を置く。ダウンロード直前にも保存セッションとチーム所属を再確認する。一時的な通信失敗後は再試行で接続を再確認し、ログイン期限切れや所属不一致の場合はログイン画面へ案内する。

Developer Portalの `services-account/v1/certificates` と `profiles` を使用し、Webセッション用のPOST＋`X-HTTP-Method-Override: GET` で読み取る。本文のTeam IDは選択中のローカルチームに固定する。CSRFヘッダーを応答から更新する。ページ送りは許可したAppleのホスト・該当リソースのパスだけを受け付け、Developer Portalへ正規化する。循環ページ・重複ID・不正な識別子を拒否する。一覧は1ページ4MiB、100ページ・10,000項目まで。

選択後に各項目の内容を取得し、JSONのリソースID・種類・base64を検証する。元ファイルは各16MiB、選択は200件、取得した元ファイルの合計は32MiBまで。内容を既存パーサーで解析し、取得できたTeam IDが保管先と違えば中止する。公開証明書やプロファイルの取得であり、既存.p8・.p12の秘密鍵取得、新規発行、更新、失効は行わない。

取得ファイルはメモリ内で既存の取り込み画面へ渡し、平文の一時ファイルを作らない。ファイルごとに所属・重複・保存先アプリを確認し、従来どおり所有者認証と暗号化保存を行う。未知の具体的なBundle IDではアプリ登録を案内する。プロファイルに複数の候補があれば明示的に選択する。キャンセル・画面ロック・スリープ時は未保存の取得データを破棄する。バックアップ形式と既存資格情報のAADは変更しない。

## 期限と検索

| 状態 | 条件 |
| --- | --- |
| 期限切れ | 期限が現在時刻と同じ、または過去 |
| 24時間以内 | 期限まで24時間未満 |
| まもなく期限 | 期限まで30×24時間以内。残り日数を切り上げて表示 |
| 有効 / 保管中 | 30日より先 / 期限なし |

削除済みは通常一覧の対象外。Dockバッジは30日以内の資格情報を重複なく数え、設定でオフにできる。

横断検索は全Team・Appの名前、Bundle ID、Team ID、ファイル名、種類、Key ID、Issuer ID等のメタデータが対象。複数語はAND検索し、元ファイル・メモ・パスワードを開かない。種別フィルターは全種類・.p8・.cer・.p12・両プロファイル形式。検索中は追加先の誤認を防ぐためファイル追加を無効化し、サイドバー移動で検索を解除する。

## バックアップと復元

フルバックアップは全Team・App・資格情報、元ファイル、メモ、保存済みパスワード、設定、削除状態を含む。金庫の暗号鍵と、Mac固有のバックアップ履歴は含めない。選択エクスポートは選んだAppと配下の全ターゲット・必要なTeam・資格情報を含め、共有ファイルは重複させず、全体設定を含めない。

保存先は毎回利用者が選び、既存ファイルを上書きしない。パスワード保護を初期値とし、パスワードなしは再確認する。バックアップ用パスワードは保存せず、忘れた場合の回復機能はない。個別書き出しは元形式で、書き出したファイルは金庫の暗号化保護の対象外になる。

### 固定形式

| 項目 | 値 |
| --- | --- |
| 拡張子・初期ファイル名 | `.xkeysbackup` / `Xkeys_yyyyMMdd_HHmmss.xkeysbackup` |
| 内容種別 | `public.data`。独自UTType登録・ファイルを開く操作からの復元は未対応 |
| 先頭 | ASCII `XKEYS` とNUL3つの8バイト、続いてbig-endian UInt32のJSONヘッダ長 |
| ヘッダ | 最大4,096バイト。version 1、protection、payloadLength、保護方式ごとの情報 |
| 保護あり | PBKDF2-HMAC-SHA256、600,000回、ランダムsalt 16バイト、導出鍵32バイト |
| 暗号文 | AES-256-GCM combined形式（nonce 12バイト・暗号文・tag 16バイト）。先頭からヘッダ末尾までをAADに使用 |
| 保護なし | JSON payloadと、ヘッダ内のSHA-256小文字hex。破損検出用で真正性は保証しない |
| パスワード | 正規化なしUTF-8、6文字以上・1,024バイト以内 |
| 内容 | snapshot.version 1。所属アプリUUID、メタデータ、元ファイルのbase64、メモ等。Dateは2001-01-01 UTCからの秒数 |
| 上限 | 元ファイル各16MiB・合計32MiB、payload 64MiB、ファイル全体64MiB+8,192バイト |
| 件数 | Team 1,000件、App・資格情報は各10,000件 |

ヘッダ・内容とも配布前に確定したversion 1だけを読み込む。形式を変える場合はversionを上げ、version 1の読み込みを残す。未知の方式・バージョン・過剰なKDF処理量・不正な所属・参照・ハッシュは拒否する。復号失敗を保護なしとして読み直さない。

### 復元と変更記録

差分を新規・重複・競合に分け、競合ごとに現在／バックアップを選択する。Team ID・Team内Bundle ID・共有範囲とハッシュが一致する項目は既存UUIDへ関連を写し替える。同じUUIDが異なる実体を指す場合は全体を拒否する。差分確認後に現在の内容が変われば、再確認を求める。

復元先に未登録のTeam IDがある場合、Apple Developerへのログインで該当チームへの所属を確認する。有効な保存セッションを再利用でき、複数のApple Accountに分かれる場合は切り替えて確認する。登録済みTeam IDだけならAppleへの接続は不要。マージ・全体置き換えとも、未登録Team IDのすべてを確認するまで保存処理を拒否する。Team名やASCのprovider IDで代用しない。

所属確認は復元計画・ローカルrevision・Team ID・確認時刻に結び付け、5分間有効とする。同じ復元操作内のアカウント切り替えでは確認を保持し、ロック・スリープ・明示的な接続解除・取消・差分更新では破棄する。永続保存する接続は最後の1アカウントだけ。復元の保存開始時とDB確定前に確認の有効性を検証し、確認中にTeam・App・資格情報を先に保存しない。脱退したチームなど、所属を確認できない未登録Teamは復元できない。バックアップ形式と旧形式の読み込みは維持する。

バックアップ状態は「バックアップが必要／バックアップ済み」と最終保存日時で表示し、変更回数・未バックアップ件数は集計しない。変更の有無を識別する印を保存し、全体バックアップ完了時は作成開始前に取得した印だけを消す。作成中に増えた印は残す。変更回数を保存していたcount属性も削除する。App・資格情報がすべて空で設定も初期値なら、Teamや過去の印が残っていてもバックアップを促さない。最近削除した項目や変更済みの設定はバックアップ対象として扱う。

マージは既存項目を残す。全体置き換えは現在の全データの事前退避が成功し、そのrevisionが差分確認時・実行時の内容と一致する場合だけ許可する。ただしTeam・App・資格情報がすべて空で設定も初期値の場合は、事前退避を不要とする。この場合も差分確認後に変更があれば実行を止める。退避の失敗・取消・その後の変更では置き換えない。既存の金庫鍵を維持し、復元blobの準備と読み戻し後、同じDB保存で参照切替と不要項目の除去を確定する。選択エクスポートなど設定を含まないバックアップでは現在の設定を保つ。

登録・編集・取り込み・メモ・削除・復元・設定等の変更を、データと同じトランザクションで記録する。フルバックアップ完了時は、スナップショットと同時に取得した変更UUID集合だけを保存済みにする。後続変更を残し、古いバックアップの完了で最新日時を巻き戻さない。個別書き出し・選択エクスポートは未バックアップ状態を解除しない。ファイル保存だけ成功し履歴更新に失敗した場合は、有効なファイルと未バックアップ表示を残す。

## 削除とCI用の書き出し

削除は認証・確認後に行い、30日間は「最近削除した項目」から復元できる。Appと専用プロファイルの関連を保持し、親Appの復元時には同時に削除した子を戻す。共有鍵の削除は保管先チームを表示する。実際の利用Appは記録していないことを示す。Apple側の失効やCI設定は変更しない。

30日以上前の削除済み項目を、次回起動・所有者認証時に完全削除する。期限切れだけの項目は対象外。未削除・保持期限未満の子がある親Appは残す。「すべて完全に削除」は確認と認証が必要。元ファイルと既存バックアップは削除せず、SSD上の物理消去を保証しない。

コピーは元ファイル（.p8 / .p12 / .cer / .mobileprovision / .provisionprofile）のbase64、Key ID、Issuer ID、保存済み.p12パスワードを1項目ずつ認証して行う。Team IDはコピー項目に含めない。値を画面に出さず、クリップボードへ直接コピーし、CIの設定画面へ貼り付ける。リポジトリ名の入力は不要。Bitrise等へは元形式で書き出す。

アプリ画面の「…」→「CI 用の Secret ファイルを作成…」で、アプリ単位の値を1つの dotenv ファイルに書き出す。利用者は各 CI の Secrets 設定に貼り付けて登録する。対象は本体と全ターゲットの期限内のプロファイル、チームの期限内の.p12とそのパスワード、チームの全.p8とKey ID・Issuer ID、Team ID。プロファイルはターゲットごとに期限が最も遅いものを、.p12は選んだプロファイルの「使う証明書」に一致するものを、.p8はASC用途で作成日時が最も新しいものだけを初期選択し、チェックで変更できる。.p8・.p12を選ぶと、そのKey ID・Issuer ID・パスワードも同時に選択・解除し、値だけを個別に外すこともできる。.cerは秘密鍵を持たないため対象外。変数名は `APPLE_TEAM_ID`・`BUILD_PROVISION_PROFILE_BASE64`（子ターゲットはBundle IDの最後の要素を挟む）・`BUILD_CERTIFICATE_BASE64`・`P12_PASSWORD`・`ASC_KEY_P8_BASE64`・`ASC_KEY_ID`・`ASC_ISSUER_ID`（ASC以外の.p8は最初の用途に応じて `APNS_KEY_P8_BASE64` など）を初期値として画面で編集でき、保存しない。.p8は一覧の用途のアイコンと名前で見分けられる。英字・数字・_（先頭は数字以外、128文字まで）に限り、`GITHUB_` で始まる名前と大文字小文字を区別しない重複を拒否する。値は単一引用符で囲み、`'` や改行を含むパスワードは書き出さずに理由を表示する。保存済みパスワードがない.p12はパスワード行をコメントにして書き出し、画面で警告する。ファイルの先頭に、Xkeysによる自動生成であること・編集せずXkeysで書き出し直すこと・生成元のアプリ名と日付・暗号化されていないことをコメントで記載する。ファイル名は保存パネルで変更でき、初期値は `<アプリ名>.ci-secrets.env`。値の読み出しは書き出し時の1回の所有者認証で行い、画面には値を表示しない。ファイルは平文で、既存ファイルを上書きせず権限0600で作る。保存データを変更しないため、未バックアップの変更として記録しない。

クリップボードへ `currentHostOnly` と `org.nspasteboard.ConcealedType` を指定し、60秒後にchangeCountが同じ場合だけ消去する。後からコピーされた内容を消さない。アプリ終了後のタイマー実行や、他アプリによる記録防止を保証しない。
