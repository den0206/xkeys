# 開発と確認状況

操作は[README](../README.md)、動作と保存形式は[DESIGN.md](DESIGN.md)、画面の参照は[モック一覧](mockups/index.html)にまとめる。

## 開発環境

- 最低対応OS：macOS 26.0（Debug・Release共通）
- 確認した環境：Apple Silicon、Xcode 27.0、Swift 6.4
- プロジェクト／scheme：`AppMate.xcodeproj` / `AppMate`
- 実装：SwiftUI、SwiftData、Apple標準フレームワーク。外部依存なし

```sh
xcode-select -p
xcodebuild -version
swift --version
```

F5は `.vscode/launch.json` から通常のDebugビルドを実行する。CodeLLDBが必要で、出力先は `.build/xcode`。署名設定はXcodeプロジェクトを使用する。テストホストの追加権限を持つアプリをF5から起動しない。

## コード構成

| 場所 | 役割 |
| --- | --- |
| `AppMate/Application/` | ウィンドウ、メニューバー、設定の構成。ヘルプから開く技術検証画面 |
| `AppMate/Models/` | Team・Appモデルと登録時の検証 |
| `AppMate/Features/` | 一覧・詳細、取り込み、編集・削除・メモ、バックアップ・復元、CIコピー、設定 |
| `AppMate/Services/` | ファイル解析、所有者認証、通知、検索、一括取り込みの探索、設定 |
| `AppMate/Persistence/` | 暗号化blob、資格情報管理、バックアップ形式・復元・変更記録 |
| `AppMateTests/` | XCTestと架空fixture。旧保存形式の互換性も確認 |
| `docs/mockups/` | 14画面と状態見本、一覧HTML。静的なデザイン参照 |

製品メタデータはSwiftData、暗号化blobはApplication Supportの `AppMateVault/blobs`、暗号鍵は端末専用Keychainへ保存する。保存先はApp Sandboxのコンテナ内。Bundle IDや署名Teamの変更時は既存データへのアクセスに注意する。

技術検証画面・検証用モデルは実装が参照しているため保持する。暗号化ファイルと鍵は製品用と分け、検証用メタデータは同じSwiftDataストアのVerificationRecordへ保存する。検証データは製品バックアップには含めない。画面からの検証は必要な場合だけ架空データで行う。

## 自動テスト

schemeのTestActionは `APP_MATE_TESTING=1` を指定する。アプリのストアはメモリ内、ファイルは一時領域の `AppMateTests` に分離する。製品の通知予約・Dockバッジ・メニューバー追加・初回案内を実行しない。認証のテストは注入した鍵を使い、製品Keychain鍵を生成しない。クリップボードのテストは専用pasteboardを使用する。

```sh
xcodebuild -project AppMate.xcodeproj -scheme AppMate \
  -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath /tmp/app-mate-tests test
```

通常ビルドと出力先を分け、Xcodeのテストホスト終了後に検証用生成物を削除する。SQLite接続を保持したホストの実行中には削除しない。製品ストア・暗号鍵・利用者設定・取り込み元・既存バックアップを削除対象に含めない。

## 確認状況

2026-10-15、最低対応OSを26.0にした構成で66件のテストと通常ビルド・署名検証が成功。検証用ストア・画像・一時ビルド・ログはテストホスト終了後に削除し、製品データ・暗号鍵・設定・F5ビルドは保持した。

| 対象 | 確認内容 |
| --- | --- |
| 自動テスト | 66件。登録・重複・解析、共有・暗号化・改ざん拒否、旧AADと旧ストアの互換性 |
| バックアップ | 保護あり／なし、形式・KDF上限、破損拒否、別金庫への復元、競合選択、失敗時のrollback |
| 追加の管理機能 | メモ更新失敗時の元参照・履歴保持、App削除時の共有鍵保持、親子の保持期限、認証取消と自動整理 |
| 検索・通知・CI | メタデータ検索、種別判定、期限の境界・DST、未バックアップ通知の1回制御、条件付きクリップボード消去 |
| 書き出し・置き換え復元 | 既存ファイルの非上書き、選択エクスポート、成功した事前退避の必須化、確認後の変更による停止 |
| macOS 26設定 | 通常ビルド・署名検証成功。Info.plistとMach-Oの最低OSが26.0 |
| 画面描画 | 1280×800と960×640で一覧・詳細の内容領域を描画 |

この表は確認した範囲を示す。リリース承認や全操作の実機検証の代わりにはしない。NSView経由の画像ではネイティブのツールバー・半透明サイドバーを完全取得できないため、全ウィンドウとモックの視覚的一致は未確認。

過去に技術検証画面でサンプルの解析、認証付き保存・再読み込み、再起動後の復号一致、元ファイル書き出し、通知許可と配送を利用者の実機で確認した。製品画面の新しい全操作を実機で確認したことは意味しない。

残る確認：

- 製品画面でのTouch ID・Macのパスワード・取消・拒否と、スリープ復帰後の通し操作
- 期限・未バックアップ通知の実配送、通知からの移動、メニューバーのウィンドウ遷移
- 全画面の長文・多数件・ライト／ダーク表示、キーボードとVoiceOver
- 配布用Bundle ID・署名・App Store審査

既知の検証時警告は、AppIntents未使用によるメタデータ抽出省略、テスト内PKCS#12解析のメインスレッド警告、テスト終了後のOSログ収集権限警告。実装に不明点がある場合はSDKヘッダとApple公式資料を確認し、認証や暗号化を省略して回避しない。
