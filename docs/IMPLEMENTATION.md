# 開発と確認状況

操作は[README](../README.md)、動作と保存形式は[DESIGN.md](DESIGN.md)にまとめる。

## 開発環境

- 最低対応OS：macOS 26.0（Debug・Release共通）
- 確認した環境：Apple Silicon、Xcode 27.0、Swift 6.4
- プロジェクト／scheme：`Xkeys.xcodeproj` / `Xkeys`
- 実装：SwiftUI、SwiftData、Apple標準フレームワーク。Apple Developer認証はXcodesLoginKitを使用

```sh
xcode-select -p
xcodebuild -version
swift --version
```

F5は `.vscode/launch.json` から通常のDebugビルドを実行する。CodeLLDBが必要で、出力先は `.build/xcode`。署名設定はXcodeプロジェクトを使用する。テストホストの追加権限を持つアプリをF5から起動しない。

## コード構成

| 場所 | 役割 |
| --- | --- |
| `Xkeys/Application/` | ウィンドウと設定の構成 |
| `Xkeys/Models/` | Team・Appモデルと登録時の検証 |
| `Xkeys/Features/` | 一覧・詳細、取り込み、編集・削除・メモ、バックアップ・復元、CIコピー、設定 |
| `Xkeys/Services/` | ファイル解析、所有者認証、検索、一括取り込みの探索、設定 |
| `Xkeys/Persistence/` | 暗号化blob、資格情報管理、バックアップ形式・復元・変更記録 |
| `XkeysTests/` | XCTestと架空fixture。旧保存形式の互換性も確認 |

製品メタデータはSwiftData、暗号化blobはApplication Supportの `XkeysVault/blobs`、暗号鍵は端末専用Keychainへ保存する。保存先はApp Sandboxのコンテナ内。Bundle IDや署名Teamの変更時は既存データへのアクセスに注意する。

技術検証画面は削除した。既存ストアを開くため、VerificationRecordのモデル定義だけをSwiftDataの型一覧に残す。以前の検証で作られたKeychain項目（`probe-key-v1`）と暗号化ファイルは、利用者データとして自動では削除しない。

## 自動テスト

schemeのTestActionは `XKEYS_TESTING=1` と言語 `ja`（地域 `JP`）を指定し、OSの言語設定にかかわらず日本語の文言で検証する。アプリのストアはメモリ内、ファイルは一時領域の `XkeysTests` に分離する。製品のDockバッジ更新・初回案内を実行しない。認証のテストは注入した鍵を使い、製品Keychain鍵を生成しない。クリップボードのテストは専用pasteboardを使用する。

```sh
xcodebuild -project Xkeys.xcodeproj -scheme Xkeys \
  -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath /tmp/xkeys-tests test
```

通常ビルドと出力先を分け、Xcodeのテストホスト終了後に検証用生成物を削除する。SQLite接続を保持したホストの実行中には削除しない。製品ストア・暗号鍵・利用者設定・取り込み元・既存バックアップを削除対象に含めない。

## 確認状況

2026-10-17時点で、全117件のXCTestと通常の署名付きDebugビルドが成功する。製品の暗号鍵・Keychain・実データ・実Apple Accountは自動テストで使わない。

| 対象 | 確認内容 |
| --- | --- |
| 登録・解析 | Team・App・ターゲットの登録と所属変更、重複拒否、各形式の解析、.p12の同梱の証明書の記録・プロファイルとの照合・パスワード保存時だけの読み直し、旧AADと旧ストアの互換性 |
| 保管・管理 | 共有範囲、暗号化と改ざん拒否、メモ・.p8用途の更新失敗時の参照保持、削除と30日保持、親子の復元、認証取消、未保存変更がある書き込みの拒否 |
| バックアップ | 保護あり／なし、形式・KDF上限、破損拒否、旧version 1 / 2の読み込み、選択エクスポート、競合復元、事前退避の必須化、確認後の変更による停止、失敗時のrollback |

| アプリアイコン | SVGの標準画像デコード・描画用データ生成・保存とバックアップへの収録、画像アイコンの復元と旧バックアップ互換性 |

この表は確認した範囲を示す。リリース承認や全操作の実機検証の代わりにはしない。架空データの値・並びは実データと異なり、画像にはOSのウィンドウ操作ボタン・シート外側・認証ダイアログを含まない。

Apple DeveloperログインにはXcodesLoginKitのリビジョン `929f9aac3140caf7b64cbb5385f4f645c5f9913d` を使い、Package.resolvedを保持する。オンライン取り込みのAPI形式はfastlaneの公開実装を参照した（コードは複製していない）：[Webセッション用読み取り](https://github.com/fastlane/fastlane/blob/master/spaceship/lib/spaceship/connect_api/provisioning/client.rb)、[証明書・プロファイルAPI](https://github.com/fastlane/fastlane/blob/master/spaceship/lib/spaceship/connect_api/provisioning/provisioning.rb)。どちらもAppleの非公開APIに依存するため、Apple側の変更に追従する保守が必要。

過去に技術検証画面で、サンプルの解析、認証付き保存・再読み込み、再起動後の復号一致、元ファイル書き出しを利用者の実機で確認した。製品画面の全操作を実機で確認したことは意味しない。

残る確認：

- 製品画面でのTouch ID・Macのパスワード・取消・拒否と、スリープ・画面ロック復帰後の通し操作
- 実Apple Accountでの認証・チーム取得・オンライン取り込み・鍵の用途取得（`account/auth/key/get` の応答形式とサービス名）、製品Keychainでの再起動後のセッション復帰、フェデレーション認証等の未対応条件の案内
- 実データの既存ストア移行とターゲット画面の手動操作
- 全画面の長文・多数件の表示（明るい表示に固定）、キーボードとVoiceOver
- 実データでのプロファイル内証明書と.p12の同梱の証明書の読み直し（初回の所有者認証後）、複数証明書を含む.p12とプロファイルのつながりの表示と、ドロップ取り込み・Touch ID 1回での一括保存の通し操作
- CI用Secretファイルの値をGitHub Actions等のSecretsに登録し、署名に使う通し操作
- 配布用Bundle ID・署名・App Store審査

既知の検証時警告は、AppIntents未使用によるメタデータ抽出省略、テスト内PKCS#12解析のメインスレッド警告、テスト終了後のOSログ収集権限警告。実装に不明点がある場合はSDKヘッダとApple公式資料を確認し、認証や暗号化を省略して回避しない。

### 関連データが残る操作の確認（2026-10-16）

| 操作 | 確認結果・対応 |
| --- | --- |
| ターゲット・本体の削除 | ターゲット単位の行と共通の確認画面を追加。登録と配下のプロファイルをまとめて削除・復元し、本体は子ターゲットも含む。破損したプロファイルがあれば登録・履歴を変更しない回帰テストを追加 |
| プロファイルだけの削除・ファイルの一括削除 | 登録を残す別操作として名称と確認文を明確化。通常のターゲット削除から分離 |
| 最近削除した項目の内訳 | 有効なターゲットだけを返す一覧を使っていたため、削除済みの子が件数に入らなかった。同時に削除され、まとめて復元される子とプロファイルの件数に修正 |
| チーム共有の鍵・証明書 | 複数アプリで使えるため、アプリ・ターゲット削除に巻き込まない。既存の共有鍵保持テストを実行 |
| チーム削除 | 所属データがあれば拒否し、完全削除が必要なことを画面に説明済み。資格情報の巻き込み削除は追加しない |
| Apple Developerログアウト | 接続情報だけを削除し、ローカルのチーム登録・資格情報は保持。接続先と保管データは別用途のため維持 |
| 元ファイル・作成済みバックアップ・Apple側の登録 | Xkeys内の削除とは独立し、削除確認で対象外と説明。自動削除は追加しない |

通常幅・最小960×640の一覧と削除確認を架空データで描画。実データ、Touch ID、右クリックとメニューからの通し操作は未確認。

バックアップ状態から変更回数の集計・件数表示を削除した。count属性も削除し、変更の印の有無で判定する。countがあるローカルDBから属性を削除しても登録・変更の印・最終保存日時が保持されること、作成中の変更・古いバックアップ完了・書き出し失敗で印が消えないこと、履歴の再起動・旧ストア移行を回帰テストで確認する。
